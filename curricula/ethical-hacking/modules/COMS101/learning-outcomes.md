## 1. Module purpose

Introduce the concepts, responsibilities and defensive practices underpinning ethical cybersecurity work. Students should understand what makes a test authorized before any technical assessment begins.

## 2. Proposed entry preparation

Basic computer literacy; no prior security training assumed.

*Recommendations only; formal prerequisites and equivalency pathways require academic approval.*

## 3. Practical, assessable learning outcomes

Upon successful completion of COMS101, a learner should be able to **independently demonstrate** the following in an expressly authorized, resettable environment. Each outcome has a tangible assessment artifact.

| Code | Practical learning outcome | Minimum observable evidence |
| --- | --- | --- |
| **LO1** | Prepare and verify an isolated, instructor-authorized cybersecurity workspace, including its target scope and recovery method. | Completed scope and lab-readiness checklist with verified reset |
| **LO2** | Inspect a supplied training system and classify its assets and data against confidentiality, integrity and availability requirements. | Asset inventory and CIA classification worksheet |
| **LO3** | Construct a threat model for an approved training scenario and prioritize at least three risks using documented likelihood and impact criteria. | Threat model and justified risk register |
| **LO4** | Configure or simulate least-privilege access for synthetic user roles and verify both allowed and denied actions. | Role-access matrix and before/after test evidence |
| **LO5** | Investigate instructor-seeded configuration or log evidence and substantiate a potential security weakness without exceeding the approved scope. | Annotated evidence and risk rationale |
| **LO6** | Write an ethical testing authorization plan specifying permitted targets, excluded activities, evidence handling and stop conditions. | Completed rules-of-engagement and authorization exercise |
| **LO7** | Apply an approved introductory security control to a disposable training fixture and demonstrate that it changes the intended security outcome. | Configuration record and before/after verification |
| **LO8** | Present a concise security baseline report linking observed evidence to impact, priority, remediation and limitations. | Technical report with defensible recommendations |

**Outcome standard:** Assess what the learner can perform, verify and justify—not only what they can define or recall. Passing a setup-readiness check is necessary before lab access but is not proof of module competence.

## 5. Proposed practical learning and assessment

Practical activities should involve hands-on demonstration and repeatable observation, accompanied by brief explanations of the findings.

| Activity | Student task and required evidence | Outcomes |
| --- | --- | --- |
| **Lab 1 — Authorized workspace** | Verify isolation, target list, recovery plan and written rules of engagement | LO1, LO6 |
| **Lab 2 — Asset and threat review** | Inventory a synthetic training service, assign CIA requirements and prioritize risks | LO2, LO3 |
| **Lab 3 — Access and configuration** | Use synthetic user roles and an approved baseline setting to produce before/after evidence | LO4, LO7 |
| **Lab 4 — Evidence-to-finding** | Investigate a seeded case and submit a short prioritized security baseline report | LO5, LO8 |

**Integrated practical exit task (proposal):** Independently establish a safe training scope, assess a supplied system for a seeded weakness, apply one approved defensive control and defend findings in a short baseline report.

**Lab gate:** Written authorization, a limited target list, safe readiness check, instructor-tested fixtures, a recovery/reset path, redacted evidence and a marking rubric are mandatory. These lab briefs remain **unpiloted proposals** until the learning environment, student instructions, reference results and marking instruments are developed and verified.

## 6. Teaching and safety boundaries

This introductory module does not require exploitation, phishing, password attacks or live target scanning. Any demonstrations use fictional cases, static traces or fully authorized training infrastructure.

Learners must seek written authorization **before** any security test, preserve privacy, refrain from testing systems outside scope and follow the instructor's stop-and-escalate procedure. Any unsafe or unapproved activity is outside this curriculum.

## 7. Practical-first assessment evidence (proposed)

- **Setup and authorization — prerequisite gate (Pass/Retry):** Independently verify that the student is operating within an approved isolated fixture and can restore the environment. This readiness check is **not** a graded learning outcome by itself.
- **Hands-on laboratory portfolio:** Assessor checks actual configuration, captured safe observations, negative/positive test cases, commands or code, and explanations linked to the LO evidence column above.
- **Integrated practical exit task:** In an unseen but equivalent instructor-owned fixture, independently complete the bounded task, investigate a seeded issue, demonstrate a defensible improvement, retest and document limitations.
- **Short knowledge checkpoint and technical explanation:** Explain why results matter and justify safety, controls, analysis and corrective action; a written definition alone cannot substitute for verified lab competence.

**Practical orientation:** A **provisional** teaching-time target is 70% supervised practical work, 20% theory/demonstration and 10% review/reporting. This is **not** an approved mark distribution, credit allocation or pass standard. Assessment weighting and moderation must be academically approved.

**Unresolved decisions:** notional/contact hours, formal academic level, credit value, prerequisite enforcement, mark weighting, pass criteria, appeals/moderation, exact lab toolchain, learner hardware, academic approval, and final safety-gate policy.
