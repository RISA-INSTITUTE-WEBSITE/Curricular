# COMS101 — Cybersecurity Fundamentals

**Level:** Introductory / progressive sequence (formal level to be decided)

## 1. Module purpose

Introduce the concepts, responsibilities and defensive practices underpinning ethical cybersecurity work. Students should understand what makes a test authorized before any technical assessment begins.

## 2. Proposed entry preparation

Basic computer literacy; no prior security training assumed.

*Recommendations only; formal prerequisites and equivalency pathways require academic approval.*

## 3. Proposed measurable learning outcomes

Upon successful completion, learners should be able to:

| Code | Learning outcome |
| --- | --- |
| **LO1** | Define confidentiality, integrity, availability and related foundational security objectives. |
| **LO2** | Distinguish threats, vulnerabilities, exploits, controls, likelihood, impact and residual risk. |
| **LO3** | Explain authentication, authorization, least privilege, defense in depth and secure configuration. |
| **LO4** | Describe common attack surfaces and security roles without conducting unsanctioned testing. |
| **LO5** | Interpret basic network, host and web security risks from controlled scenarios. |
| **LO6** | Recognize legal, ethical, privacy and professional boundaries, including written authorization and rules of engagement. |
| **LO7** | Construct a simple asset inventory and threat model for an approved training system. |
| **LO8** | Produce a concise security-risk report recommending proportionate controls and safe next steps. |

## 4. Teaching-section alignment

| Section | Core content | Outcomes |
| --- | --- | --- |
| **A — Foundations** | Security objectives, terminology, exposure and risk | LO1–LO2 |
| **B — Defensive Security Principles** | Identity, access control, security controls and baseline hardening | LO3–LO4 |
| **C — System and Threat Context** | Basic network, endpoint and application risks; threat modeling | LO4–LO5, LO7 |
| **D — Ethics and Professional Practice** | Permission, legal limits, rules of engagement, privacy, stop conditions and disclosure | LO6 |
| **E — Risk Reporting** | Evidence quality, risk prioritization and stakeholder communication | LO7–LO8 |

The teaching sections, learning outcomes and sequencing are **new syllabus proposals**, not a verbatim transcription of the handwritten list.

## 5. Proposed practical learning and assessment

| Activity | Learning task / evidence | Outcomes |
| --- | --- | --- |
| **Written-scope exercise** | Distinguish permitted and prohibited actions in realistic testing scenarios; identify stop conditions | LO6 |
| **Threat-model workshop** | Inventory a fictional or instructor-owned training service and map assets, threats and controls | LO2, LO7 |
| **Risk-register exercise** | Evaluate a pre-supplied vulnerability case and draft practical mitigations | LO2, LO3, LO8 |

Each lab requires a written scope and authorized target list, readiness verification, instructor-tested fixtures, a recovery/reset procedure, sanitized evidence, and a rubric. Activities are proposals until lab scripts, guides, model results and marking criteria are reviewed and piloted.

## 6. Teaching and safety boundaries

This introductory module does not require exploitation, phishing, password attacks or live target scanning. Any demonstrations use fictional cases, static traces or fully authorized training infrastructure.

Learners must seek written authorization **before** any security test, preserve privacy, refrain from testing systems outside scope and follow the instructor's stop-and-escalate procedure. Any unsafe or unapproved activity is outside this curriculum.

## 7. Proposed assessment evidence

- **Knowledge checkpoint:** Explain key concepts and ethical scope constraints for the module.
- **Setup readiness (Pass/Retry):** Verify isolation, target authorization, basic tools and rollback method before practical tasks.
- **Practical task(s):** Submit independently explainable, sanitized outputs, observations and remediation/retest evidence.
- **Final module assessment:** Analyze a permitted case, justify findings and communicate security improvements with limitations.

**Unresolved decisions:** contact/notional hours, formal academic level, credit value, prerequisite enforcement, assessment weighting, pass criteria, appeals/moderation, exact lab toolchain, equipment needs and academic approval.
