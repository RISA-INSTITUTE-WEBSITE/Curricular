## 1. Module purpose

This introductory module develops students' understanding of how computers work internally, how digital information is represented using bits, and how computer hardware stores, processes and transfers that information.

CS101 provides a foundation for subsequent Computer Science modules, particularly CS102 — Programming Fundamentals.

## 2. Proposed module learning outcomes

**Upon successful completion of CS101, students should be able to:**

| Code | Learning outcome |
| --- | --- |
| **LO1** | Identify and explain the functions of major computer components, including the CPU, registers, cache, main memory and input/output systems. |
| **LO2** | Illustrate and explain how the CPU executes instructions through the fetch–decode–execute cycle. |
| **LO3** | Differentiate between registers, cache and main memory based on their functions, speed, capacity and role in program execution. |
| **LO4** | Explain how the CPU, memory and input/output systems interact when a computer executes a program. |
| **LO5** | Perform conversions between decimal, binary and hexadecimal number systems and apply these representations to computing problems. |
| **LO6** | Represent and interpret unsigned integers, signed integers and floating-point numbers in binary, including basic limitations of computer number representation. |
| **LO7** | Explain and apply character encoding systems, including ASCII and Unicode, to represent textual information. |
| **LO8** | Describe how digital images and sound are encoded, and calculate basic storage requirements using resolution, bit depth and sampling information. |
| **LO9** | Analyse simple scenarios to explain how hardware components process, store and transfer binary data. |
| **LO10** | Use basic computing tools or simulations to investigate computer hardware characteristics, data representation and instruction execution. |

## 3. Learning outcomes by teaching section

### Section A — Computer Architecture

**Mapped outcomes:** LO1, LO2, LO3, LO4

**Content focus:**
- CPU, registers, cache, main memory and input/output systems
- Fetch–decode–execute cycle
- Memory hierarchy and comparison of memory components
- Hardware interactions during program execution

### Section B — Data Representation

**Mapped outcomes:** LO5, LO6, LO7, LO8

**Content focus:**
- Decimal, binary and hexadecimal number systems
- Unsigned and signed integer representations
- Introductory floating-point representation and limitations
- ASCII and Unicode character encoding
- Digital image and audio encoding
- Elementary storage-size calculations

### Section C — Integrated Applications and Practical Work

**Mapped outcomes:** LO9, LO10, drawing on LO1–LO8

**Content focus:**
- Tracing simple program-execution scenarios
- Identifying how hardware handles binary data
- Investigating hardware and data-representation concepts through accessible tools or simulations

## 4. Suggested practical learning and assessment activities

The following are **proposed** exercises to help demonstrate the outcomes; they are not a finalized assessment specification.

| Practical activity | Outcomes assessed |
| --- | --- |
| Inspect CPU, memory and cache information on a computer. | LO1, LO3, LO10 |
| Simulate and explain the fetch–decode–execute cycle. | LO2, LO4 |
| Convert numbers between bases and investigate binary integer overflow. | LO5, LO6 |
| Encode and decode text using ASCII and Unicode. | LO7 |
| Calculate image and audio storage requirements from given parameters. | LO8 |
| Trace how a simple program uses the CPU, memory and I/O systems. | LO4, LO9 |

## 5. Recommended teaching boundaries

- **Primary conceptual outcomes:** LO1–LO8 establish the core knowledge and skills.
- **Applied outcomes:** LO9–LO10 integrate that knowledge through analysis, tools and simulation.
- **Relationship with CS102:** CS101 should not require students to write substantial programs. Writing, executing and debugging programs should be emphasized in **CS102 — Programming Fundamentals**.
- **Level of depth:** Introduce core architectural concepts and basic representations, while postponing detailed microarchitecture or advanced numerical formats to later study where appropriate.
